## 一、概述

### 1. 需求背景

#### 目标用户现状

DiskGuard 面向 Windows 个人用户与开发者，以桌面宠物形态被动监控磁盘空间。用户当前已经可以：

- 扫描 C／D／E 等磁碟并生成一份综合清理报告；
- 按 A／B／C 安全等级选择项目；
- 手动确认后执行删除；
- 查看每次删除的 manifest、结果 JSON、逐项 journal 与 Markdown 日志；
- 选择是否启用目前的小项 ZIP 备份能力。

但现有记录主要面向开发者排查，普通用户很难快速回答：

- 上一次到底删了哪些内容？
- 哪些项目完全移除，哪些仍有残留？
- 哪些记录有实体备份，哪些只有审计记录？
- 这次删除是否包含较高风险路径？
- 删除前是否能先看清完整影响，再决定是否执行？

#### 核心痛点

**删除前风险不够直观，删除后记录难以浏览，且现有小项备份容易被误解为完整恢复保障。**

#### 当前问题汇总

| 问题点 | 问题描述 | 当前影响 |
|---|---|---|
| 历史记录不可读 | manifest、result、journal、log 分散为多个文件 | 用户无法快速回溯一次清理 |
| 记录字段不统一 | v1.1.0 前后部分字段缺失或语义不同 | 无法直接做统一列表与筛选 |
| 风险提示偏文案化 | 确认弹窗主要展示路径和总量 | 用户难以快速判断本次删除的风险等级 |
| 备份语义不清晰 | `<100 MB` ZIP 只是小项应急副本 | 用户可能误以为所有删除都可恢复 |
| 备份默认开启 | 当前自动为符合条件的小项创建 ZIP | 增加 IO 与空间开销，但收益有限 |
| 历史查询依赖服务 | 现有报告页只有本机 serve 模式可执行操作 | 需要明确历史页的降级路径 |

### 2. 需求目标

#### 业务目标

1. 让用户在 30 秒内看懂一次历史清理的范围、结果与备份状态。
2. 让用户在最终确认前看到统一、可验证的风险摘要与备份计划。
3. 在不引入云同步、完整备份或恢复系统的前提下，提升安全可感知度。

#### 成功标准

| 指标 | 当前状态 | 目标状态 |
|---|---|---|
| 历史记录索引 | 无统一索引 | 每次删除完成后 2 秒内可查询 |
| 历史列表性能 | 需手动翻文件 | 50 条列表本地查询 P95 ≤ 500 ms |
| 风险预览 | 仅前端展示路径 | 后端统一预览，P95 ≤ 500 ms／1000 项 |
| 备份默认行为 | 符合条件的小项默认 ZIP | 默认关闭，仅用户明确启用时创建 |
| 误删确认 | 单层确认弹窗 | 按风险等级执行一至两层确认 |
| 旧记录兼容 | 字段不完整 | 可导入并明确标记“旧记录未知项” |
| 索引故障影响 | 无索引 | SQLite 故障不阻塞删除，自动降级到原始 JSON |
| 安全承诺 | 易被理解为可恢复 | 全流程不再宣称“一键恢复”或“完整备份” |

### 3. 需求范围

#### 包含

- 清理历史与审计页面。
- 现有 manifest／result／journal／last_delete／ZIP 的自动索引与迁移。
- 历史列表、筛选、分页与详情查看。
- 删除前统一风险预览 API。
- 风险等级、路径分类、字节总量、父子重叠、特殊动作与备份计划摘要。
- 可选 ZIP 备份开关，默认关闭。
- 按风险等级执行分级确认。
- SQLite 索引损坏或不可用时的降级方案。
- 相关自动化测试、文档与发布说明。

#### 不包含

- 动态空间预测或耗尽时间预测。
- 轻量级空间占用可视化，保留为下一候选版本。
- 关键目录监控，例如 `D:\Games` 独立阈值。
- 一键恢复、完整备份、外部硬碟或云端备份。
- 自动删除、无人值守清理。
- 通用清理器、卸载器或软件管理功能。
- 开发者缓存识别扩展，例如 `node_modules`、`.venv`、`target`。
- 账号体系、遥测、广告或任何联网服务。

## 四、功能说明

### 功能 1：清理历史与审计

#### 功能描述

用户可在“清理历史与审计”页面查看历次删除的时间、范围、结果、残留和备份状态，并进入单次详情查看逐项记录与原始审计文件。

SQLite 只作为**可重建的查询索引**；现有 JSON、JSONL journal、Markdown 与 ZIP 仍是权威审计附件。索引损坏或丢失时，不影响删除执行，也不影响用户手动查看原始文件。

#### 用户流程

```text
打开清理历史
  ↓
读取 SQLite 索引
  ├─ 索引存在且 schema 兼容 → 查询列表
  ├─ 索引不存在 → 扫描 data 下现有审计文件并导入 → 查询列表
  ├─ 索引损坏 → 重命名损坏文件 → 从 JSON／journal 重建 → 查询列表
  └─ 重建失败 → 进入降级模式，显示原始文件目录与说明
  ↓
选择筛选条件
  ├─ 有记录 → 显示 50 条分页列表
  └─ 无记录 → 显示空状态
  ↓
点击一条记录
  ├─ 详情完整 → 显示摘要、逐项结果、附件状态
  ├─ 部分附件缺失 → 显示“部分审计附件已缺失”
  └─ 详情读取失败 → 保留列表并显示可重试错误
```

#### 状态机

| 状态名称 | 进入条件 | 退出条件 | 用户可见表现 |
|---|---|---|---|
| LOADING | 首次打开历史页 | 索引查询或重建完成 | 显示“正在读取清理记录…” |
| REBUILDING | 索引不存在、schema 过旧或损坏 | 重建成功／失败 | 显示“正在从现有审计文件重建索引…” |
| READY | 查询成功 | 用户筛选或打开详情 | 显示历史列表 |
| EMPTY | 查询结果为空 | 用户修改筛选或执行新清理 | 显示“尚无清理记录” |
| FILTERING | 用户修改筛选条件 | 查询返回 | 列表显示轻量加载状态 |
| DETAIL_LOADING | 点击记录 | 详情返回 | 显示“正在读取详情…” |
| DETAIL_READY | 详情读取成功 | 关闭详情或选择其他记录 | 显示详情抽屉 |
| DEGRADED | SQLite 不可用或重建失败 | 用户重试或重启服务 | 显示原始 JSON 目录与降级说明 |
| ERROR | 非索引类读取错误 | 用户重试 | 显示错误原因与重试按钮 |

#### 字段规范

| 字段名 | 类型 | 是否必填 | 长度限制 | 校验规则 | 错误提示 |
|---|---|---|---|---|---|
| keyword | 文本 | 否 | ≤ 128 字符 | 去除首尾空白；不区分大小写；匹配路径、盘符、状态 | “搜索关键词不能超过 128 个字符” |
| drive | 枚举 | 否 | 单值 | ALL／C／D／E…；仅允许本次历史出现过的盘符 | “无法读取所选磁碟记录” |
| status | 枚举 | 否 | 单值 | ALL／EXECUTED／PARTIAL／ABORTED／REJECTED／NOOP | “状态筛选无效” |
| backup_status | 枚举 | 否 | 单值 | ALL／COMPLETE／NOT_REQUESTED／SKIPPED_SPACE／FAILED／UNKNOWN | “备份状态筛选无效” |
| page | 整数 | 否 | ≥ 1 | 默认 1；每页固定 50 条 | “页码无效” |

#### 文案规范

| 场景 | 文案内容 |
|---|---|
| 空状态 | “尚无清理记录。完成一次手动清理后，记录会出现在这里。” |
| 加载中 | “正在读取清理记录…” |
| 索引重建 | “正在从现有审计文件重建索引，请稍候。” |
| 操作成功 | “清理记录已载入。” |
| 详情读取失败 | “无法读取这次清理的详情，请重试或查看原始审计文件。” |
| 权限不足 | “无法读取部分审计文件。DiskGuard 只会显示当前账号有权限访问的内容。” |
| 网络异常 | “本机历史服务未响应，请确认 DiskGuard 本机服务正在运行。” |
| 降级模式 | “历史索引暂时不可用；删除功能不受影响，可前往 data 目录查看原始 JSON 与日志。” |
| 备份未知 | “旧记录未记录备份完整性，无法确认是否可恢复。” |
| 无备份 | “本次未创建实体备份，仅有审计记录。” |

#### 异常情况处理

| 异常场景 | 触发条件 | 处理方式 | 用户反馈 |
|---|---|---|---|
| SQLite 不存在 | 首次使用历史页 | 自动创建并导入现有文件 | 显示重建进度 |
| SQLite 损坏 | 打开或查询失败 | 重命名为 `history.db.corrupt.<timestamp>`，重新构建 | 显示一次降级提示 |
| schema 过旧 | 版本号不兼容 | 备份旧 DB，执行只读迁移或重建 | 显示“正在升级历史索引” |
| JSON 字段缺失 | 导入旧版记录 | 按保守规则补默认值，未知字段保留 NULL | 详情显示“旧记录未知项” |
| journal 缺失 | manifest 指向的 JSONL 不存在 | 使用 result 的 outcomes；仍缺失则标记不完整 | 显示“逐项日志缺失” |
| ZIP 缺失 | 备份路径不存在 | 备份状态改为 MISSING | 显示“备份文件已缺失” |
| ZIP 损坏 | ZIP 结构校验失败 | 标记 CORRUPT，不提供任何恢复入口 | 显示“备份文件损坏” |
| 路径无权限 | 当前账号无法读取附件 | 跳过该附件并记录错误 | 显示权限提示 |
| 服务未启动 | 历史页请求失败 | 提示从桌宠菜单启动本机服务 | 显示网络异常文案 |
| 索引写入失败 | 磁盘满或 DB 被占用 | 历史页进入 DEGRADED；删除继续写 JSON | 不影响删除，只提示历史暂不可用 |

### 功能 2：删除前风险摘要与可选备份

#### 功能描述

用户在清理报告选择项目后，先调用后端预览接口，获取统一验证后的风险摘要。确认弹窗展示：

- 本次选择数量、原始总字节、扣除父子重叠后的有效字节；
- 各盘符、各安全等级、各动作类型的数量；
- 是否存在 B 级项目、个人目录、大体积目录或特殊动作；
- 本次是否创建 ZIP 备份、预计备份字节与所需空间；
- 扫描是否过期、目标是否仍存在、是否已变成 reparse point。

ZIP 备份默认关闭。用户明确启用后，才为小于配置阈值的直接删除项目创建本机 ZIP；启用后若空间不足或写入不完整，阻止删除。

本功能**不提供恢复按钮，也不宣称删除可撤销**。

#### 用户流程

```text
在清理报告勾选项目
  ↓
点击“执行删除”
  ↓
调用 /api/delete/preview
  ├─ 验证失败 → 显示被拒绝项目与原因，不进入确认
  ├─ 扫描过期 → 要求重新分析
  ├─ 目标不存在／变成链接 → 从本次集合剔除并提示
  └─ 验证成功 → 显示风险摘要
  ↓
查看风险等级与备份计划
  ├─ 保持备份关闭 → 显示“本次不会创建 ZIP 副本”
  └─ 启用备份
      ├─ 空间充足 → 显示预计备份大小
      ├─ 空间不足 → 禁用备份开关与最终确认，提示释放空间或关闭备份
      └─ 规则无符合项 → 显示“没有符合备份条件的项目”
  ↓
按风险等级确认
  ├─ LOW → 点击“确认删除”
  ├─ MEDIUM → 输入“确认清理”
  └─ HIGH → 输入“确认删除”
  ↓
调用 /api/delete，backend 再次即时验证
  ├─ 通过 → 执行删除并显示进度
  ├─ 备份写入不完整 → 中止，尚未删除任何目标
  ├─ 第二个删除请求 → 返回 409 BUSY
  └─ 即时验证失败 → 返回 REJECTED，不删除
  ↓
显示执行结果与历史记录入口
```

#### 状态机

| 状态名称 | 进入条件 | 退出条件 | 用户可见表现 |
|---|---|---|---|
| IDLE | 未选择项目或未点击删除 | 点击删除 | 删除按钮不可用或可点击 |
| PREVIEW_LOADING | 已请求预览 | 预览返回 | 显示“正在验证本次清理范围…” |
| PREVIEW_READY | 预览成功 | 修改备份开关或进入确认 | 显示风险摘要 |
| PREVIEW_REJECTED | 预览无有效目标 | 重新选择或重新扫描 | 显示拒绝原因 |
| BACKUP_CHECKING | 用户启用备份 | 空间检查完成 | 显示“正在检查备份空间…” |
| BACKUP_BLOCKED | 备份空间不足 | 关闭备份或释放空间 | 禁用最终确认 |
| CONFIRM_REQUIRED | 中／高风险 | 输入正确短语 | 确认按钮保持禁用 |
| SUBMITTING | 已提交最终删除 | 后端接受／拒绝 | 显示“正在启动清理…” |
| RUNNING | 删除进行中 | 完成／中止／部分残留 | 显示进度与当前路径 |
| EXECUTED | 全部目标满足删除条件 | 用户关闭结果 | 显示全部完成 |
| PARTIAL | 有目标未满足条件 | 用户关闭结果 | 显示残留数量 |
| ABORTED | 备份、审计写入或外部中止 | 用户关闭结果 | 显示中止原因 |
| BUSY | 已有删除作业 | 用户关闭提示 | 显示“已有删除作业正在进行” |
| ERROR | 非预期错误 | 用户重试 | 显示错误详情 |

#### 字段规范

| 字段名 | 类型 | 是否必填 | 长度限制 | 校验规则 | 错误提示 |
|---|---|---|---|---|---|
| backup_enabled | 布尔 | 是 | 固定 | 默认 false；true 时才检查空间与创建 ZIP | “无法启用本次备份” |
| confirmation_phrase | 文本 | 条件必填 | ≤ 16 字符 | MEDIUM 必须精确等于“确认清理”；HIGH 必须精确等于“确认删除” | “请输入指定确认短语” |
| paths | 路径数组 | 是 | 1–5000 项 | 每项为非空绝对路径；后端再按扫描范围验证 | “清理选择为空或格式无效” |
| token | 文本 | 是 | 固定 | 必须等于本次本机服务 token | “授权已失效，请重新打开页面” |

#### 风险等级规则

| 风险等级 | 判定规则 | 确认要求 |
|---|---|---|
| LOW | 全部为 A 级；动作仅为 direct 或 thumbcache_only；总有效字节 < 1 GiB；无 denied 项 | 一次确认 |
| MEDIUM | 任一 B 级项目；或总有效字节 ≥ 1 GiB；或包含直接删除的个人目录 | 输入“确认清理” |
| HIGH | 任一 `empty_recycle_bin`；或路径位于 `Downloads`／`Documents`／`Pictures`／`Videos`；或总有效字节 ≥ 10 GiB | 输入“确认删除” |

若同时命中多个等级，取最高等级。C 级、锁定项、设定排除项、reparse point 与过期扫描不进入风险确认，直接拒绝。

#### 备份规则

- 配置新增 `delete.backup_enabled`，默认 `false`。
- `small_backup_mb` 继续作为备份阈值，默认 `100`。
- 仅 `action=direct` 且单项原始字节小于阈值的项目进入 ZIP。
- 备份预估以父子去重后的有效集合计算。
- 所需可用空间为：`预计备份原始字节 × 2 + 200 MiB` 安全余量。
- 备份关闭时：不创建 ZIP，不进行备份 IO；结果记录 `backup_status=NOT_REQUESTED`。
- 备份开启且空间不足：禁用最终确认，不允许静默降级为无备份删除。
- 备份开启但写入不完整：删除尚未开始即中止。
- 历史页只显示备份状态，不提供恢复操作。

#### 文案规范

| 场景 | 文案内容 |
|---|---|
| 预览加载 | “正在验证本次清理范围…” |
| 低风险摘要 | “本次为低风险清理，请确认路径与大小无误。” |
| 中风险摘要 | “本次包含 B 级项目或较大目录，请输入“确认清理”继续。” |
| 高风险摘要 | “本次包含高影响路径或特殊动作，请输入“确认删除”继续。” |
| 备份关闭 | “本次不会创建 ZIP 副本；删除后仅保留审计记录。” |
| 备份开启 | “本次将为本机小项创建 ZIP 副本，预计需要约 X MiB。” |
| 备份空间不足 | “备份碟剩余空间不足，无法启用本次备份。请释放空间或关闭备份。” |
| 备份不完整 | “备份写入不完整，已阻止删除；尚未删除任何目标。” |
| 操作成功 | “清理已完成，可在“清理历史与审计”查看完整记录。” |
| 部分残留 | “清理已结束，但有 N 项仍有残留，请查看详情。” |
| 权限不足 | “当前账号无法读取或删除部分目标，请以有权限的账号重试。” |
| 网络异常 | “本机服务未响应，请重新打开清理报告。” |
| 扫描过期 | “扫描结果已过期，请重新分析后再删除。” |
| 目标已变化 | “部分目标已不存在或已变成链接，已从本次清理中剔除。” |
| BUSY | “已有删除作业正在进行，请等待完成后再试。” |

#### 异常情况处理

| 异常场景 | 触发条件 | 处理方式 | 用户反馈 |
|---|---|---|---|
| 未选择项目 | paths 为空 | 不调用预览 | 删除按钮禁用 |
| 扫描过期 | scan.created 超过 max_age_hours | 返回 REJECTED | 要求重新分析 |
| 目标不存在 | 即时 lstat 失败 | 从预览集合剔除 | 显示被剔除路径 |
| 目标变成 reparse point | 属性包含 FILE_ATTRIBUTE_REPARSE_POINT | 拒绝该项目 | 显示安全原因 |
| 输出目录与目标重叠 | commonpath 命中 data／backups | 拒绝该项目 | 显示保护说明 |
| 备份空间不足 | free_bytes 低于安全需求 | 禁用备份与确认 | 显示空间不足文案 |
| 备份 I/O 错误 | ZIP 写入或走档失败 | 标记 backup_status=FAILED，删除不开始 | 显示备份不完整文案 |
| 确认短语错误 | 输入与风险等级要求不一致 | 保持确认按钮禁用 | 显示字段错误 |
| 服务 token 失效 | token 不匹配 | 返回 403 | 要求重新打开页面 |
| 并发删除 | 第二个删除请求 | 返回 409 BUSY | 显示 BUSY 文案 |
| 审计 checkpoint 失败 | manifest 无法写入 | 中止下一批 | 显示 ABORTED 与原因 |
| SQLite 索引失败 | 历史 DB 写入失败 | 不影响删除；JSON 仍写入 | 结果页提示历史暂不可用 |

## 五、技术方案与数据设计

### 1. 总体原则

- SQLite 是**派生索引**，不是唯一审计真相。
- 删除流程继续以原子 JSON、JSONL journal 与 Markdown 为权威记录。
- 历史页只读展示，不修改、不清理、不恢复任何文件。
- 所有 API 仅绑定 `127.0.0.1`，不引入外部网络请求。
- 备份是可选的应急副本，不是数据安全保证。

### 2. SQLite 数据模型

### 3. 导入规则

- 首次打开历史页或服务启动后台任务时执行增量导入。
- 扫描以下文件：
  - `execution_result_*.json`
  - `execution_manifest_*.json`
  - `*.outcomes.jsonl`
  - `last_delete.json`、`last_delete_<X>.json`
  - `backups/*.zip`
- 以 `source_signature` 去重；文件未变化时不重复解析。
- 多碟合计记录作为父运行，`per_drive` 引用的单碟 result／manifest 作为子运行导入。
- v1.1.0 旧结果缺少 `bytes` 时，由 `mb × 1048576` 估算并标记 `estimated=true`。
- 旧结果缺少 `satisfied` 时：
  - direct 动作可由 `after=false` 推断；
  - thumbcache_only／empty_recycle_bin 一律保留 NULL，不推断成功。
- 旧备份缺少 `complete` 时标记 `UNKNOWN`，即使 ZIP 存在也不宣称完整。
- 导入过程单事务提交；失败回滚，不留下半套索引。

### 4. API 设计

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/history` | 历史页面 |
| GET | `/api/history` | 历史列表与筛选 |
| GET | `/api/history/{run_id}` | 单次运行详情 |
| POST | `/api/delete/preview` | 风险预览与备份计划 |
| POST | `/api/delete` | 最终删除；新增 `backup_enabled` 字段 |

`/api/history` 查询参数：`keyword`、`drive`、`status`、`backup_status`、`page`。

`/api/delete/preview` 返回：

- `targets`：验证后的目标路径、字节、等级、动作；
- `rejected`：被剔除项目与原因；
- `risk_level` 与 `risk_reasons`；
- `target_bytes`、`effective_bytes`；
- `drive_counts`、`tier_counts`、`action_counts`；
- `backup_plan.enabled`、`eligible_count`、`estimated_bytes`、`required_free_bytes`、`available_bytes`、`can_enable`。

最终 `/api/delete` 必须重新执行即时验证，不信任前端预览结果。

### 5. 配置变更

`config.json` 新增：

```json
"delete": {
  "backup_enabled": false,
  "small_backup_mb": 100
}
```

兼容规则：

- 未配置 `backup_enabled` 时按 `false` 处理。
- CLI 增加 `--backup`；未传时按配置默认值。
- API 未传 `backup_enabled` 时按 `false` 处理。
- 旧的手动 ZIP 仍可在历史中显示，但不会新增恢复入口。

### 6. 降级策略

- `history.db` 损坏：重命名后从 JSON／journal 重建。
- 重建失败：历史页进入 DEGRADED，显示 `data` 目录路径与原始文件说明。
- 索引写入失败：不影响删除；JSON、journal、result 继续写入。
- 历史服务未启动：报告页显示“清理历史需启动本机服务”，不阻塞离线报告查看。
- SQLite 查询超时：限制单页 50 条、详情最多 5000 项；超出时提示缩小筛选范围。

## 七、验收标准

### 功能验收

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| AC-01 | 历史导入 | v1.1.0 现有 result／manifest／journal 可导入且重复执行不重复 |

| AC-05 | 历史详情 | 展示逐项路径、字节、动作、前后状态、残留与附件状态 |
| AC-06 | 索引降级 | DB 损坏或不可用时删除仍可执行，历史页显示降级说明 |
| AC-07 | 风险预览 | 前端展示与后端 preview 完全一致 |
| AC-08 | 备份默认关闭 | `backup_enabled=false` 时不创建 ZIP、不进行备份 IO |
| AC-09 | 备份启用 | 符合条件的小项生成唯一归档名 ZIP，完整后才允许删除 |
| AC-10 | 备份失败 | 空间不足或写入不完整时删除不开始 |
| AC-11 | 分级确认 | LOW／MEDIUM／HIGH 按规则触发对应确认方式 |
| AC-12 | 最终再验证 | preview 后目标发生变化时，final 重新拒绝或剔除 |
| AC-13 | 并发删除 | 第二个请求返回 BUSY／409，不破坏审计文件 |
| AC-14 | 无恢复承诺 | 页面、日志、Release 文案均不出现“一键恢复”或“完整备份” |

### 性能验收

| 项目 | 目标 |
|---|---|
| 1000 项风险预览 | P95 ≤ 500 ms |
| 50 条历史列表查询 | P95 ≤ 500 ms |
| 5000 项详情序列化 | P95 ≤ 1 s |
| 备份关闭的删除准备 | 不调用 `backup_small`，不产生备份目录 IO |
| 重复导入 | 文件签名未变化时不重新解析 JSON |
| 空闲历史服务 | 不周期全量扫描 data 目录 |

### 安全验收

- 所有新增服务仅绑定 `127.0.0.1`。
- 不引入外部 HTTP 请求、遥测或云存储。
- 历史页展示完整路径，但不记录到任何外部日志。
- 删除最终阶段继续检查扫描过期、reparse point、输出目录重叠与互斥锁。
- SQLite 故障不得绕过 JSON 审计写入或删除安全校验。

| UI 验收 | 空、加载、成功、失败、权限、服务未启动 | 六类状态文案与操作完整 |

## 九、风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| SQLite 被误当成唯一审计真相 | 索引损坏后记录消失 | 明确 JSON／journal 为权威，DB 可重建 |
| 旧记录字段不足 | 错误推断历史结果 | 未知项保留 NULL，特殊动作不推断 |
| 备份默认关闭改变既有行为 | 用户升级后认为备份消失 | Release 明确说明；配置保留 `small_backup_mb`；历史标记 NOT_REQUESTED |
| 历史路径包含敏感信息 | 隐私风险 | 仅本机回环服务；不写外部日志；不提供云同步 |
| preview 与 final 逻辑漂移 | 预览与真实删除不一致 | 共享同一验证与风险函数；final 再即时验证 |
| 历史页依赖本机服务 | 离线时不可用 | 离线报告仍可查看；历史页给出启动服务指引 |
| 4 周范围膨胀 | 延期或质量下降 | 严格冻结 P0；动态预测、恢复、关键目录监控不进入本阶段 |

### 1. 为什么 1.2 没有出现在本阶段功能列表

因为本 PRD 是已确认的 **4 周 MVP**，不是附件建议的全量排期。当前阶段优先解决两个直接影响信任的问题：

1. 删除后无法快速查证；
2. 删除前风险与备份语义不够清楚。

轻量可视化属于“信息呈现增强”，可以复用现有扫描数据，但它不会直接降低误删概率，也没有解决备份不完整的结构性问题。因此将它从 P0／P1 功能列表移到**后续候选版本**，并不代表建议被否定。

### 2. 建议的未来开展顺序

| 建议版本 | 主题 | 主要内容 | 进入条件 |
|---|---|---|---|
| v1.2.0 | 安全与审计 | 本 PRD：历史、风险预览、可选备份、分级确认 | 4 周 P0 验收通过 |
| v1.3.0 | 看得懂与少打扰 | 1.2 轻量可视化、4.1 智能免打扰 | 历史页稳定；可视化不增加全盘扫描 |
| v1.4.0 | 更灵活但仍安全 | 2.1 受限规则自定义、3.1 开发者缓存识别 | 建立规则版本、预览与回滚机制 |
| v1.5.0 | 更前瞻与更广覆盖 | 1.1 动态预测、3.2 关键目录监控、4.2 极简模式 | 至少有 14 天连续样本；目录监控安全模型通过评审 |

### 3. 未来功能的共同必要性

- **安全与信任**：历史、审计、受限规则是基础，优先级最高。
- **守护感**：可视化与动态预测让用户更早理解空间趋势，但必须建立在可信数据上。
- **能力覆盖**：开发者缓存与关键目录监控扩展使用场景，但必须保持 B 级、手动确认与明确安全边界。
- **无扰体验**：免打扰与极简模式提升长期驻留意愿，不应干扰核心预警。
